MCTC-KZ-B0S 测试方案 · 安卓 APP 与 APK 打包指南

电梯协议转换板 1-5 层测试 · 手机端方案 · 生成日期 2026-09-03

结论：能做，代码已经做完并验证通过。 手机没有 RS485 串口，所以安卓版不走串口，改成手机 WiFi → 串口服务器（NA11x / C2000）→ RS485 → 协议转换板， 功能与 Windows 桌面版一一对应（一键读五类状态、1-5 层前门、开关门、司机、持续开门、AGV 进出与心跳、通信日志）。
唯一的坎是出 APK 需要 Linux 构建环境——这台 Win7/Win10 机器上没有 Android SDK、Java、WSL、Docker， 所以推荐用 GitHub Actions 云构建（零安装，约 20-40 分钟出包）。

一、安卓上的连接拓扑（与桌面版的差别）

  桌面版（现在）
  PC ──USB/485 转换器── 或 ──网线/WiFi── 串口服务器 ──RS485 38400/8N1── 协议转换板 ── 电梯主控

  安卓版 · 网络模式（默认）
  手机 ──WiFi TCP── 串口服务器(NA11x 192.168.3.7:8887 / C2000 192.168.4.1:8000)
                          └─ RS485 38400/8N1 ── 协议转换板 ── 电梯主控

  安卓版 · USB-OTG 直连（免串口服务器）
  手机 ──OTG 线── USB转485(FTDI/CP210x/CH340/PL2303) ── RS485 38400/8N1 ── 协议转换板 ── 电梯主控
  • 串口侧的 38400/8/N/1 仍然要在串口服务器网页里配，手机管不到这一段；手机只负责 TCP 那一段。
  • 串口服务器两种模式要和 APP 里的选择对应：透明/透传 → APP 选「Modbus RTU 透传」； 开了 Modbus 网关 → APP 选「Modbus TCP 网关」。选错就是收不到任何响应。
  • USB-OTG 直连现已支持（APP 里"连接方式"选「USB OTG 直连」）：手机经 OTG 线接 USB 转 485，走纯 Modbus RTU，串口参数固定 38400/8N1，无需串口服务器，适合没 WiFi 的现场。限制：转换器芯片须为 FTDI/CP210x/CH340/PL2303 之一，且手机已开启 OTG（详见第五章）。

三、出 APK 的三条路线（推荐第一条）

路线评价说明与代价
GitHub Actions 云构建 推荐 本机零安装。把 MCTC_Android 推到 GitHub，打一个 v1.0.0 标签， Actions 自动跑 Buildozer，20-40 分钟后在 Artifacts 里下载 APK。缺点是仓库要公开或占用私有仓库额度， 且首次构建需要联网下载 Android SDK/NDK。
WSL2 + Buildozer 本地构建 备选 需要在这台机器上装 WSL2（Ubuntu 22.04）+ 一堆 Linux 依赖，约 10GB 磁盘，首次编译同样半小时以上。 好处是后续改代码出包快、不依赖网络。Win7 不支持 WSL2，只能在 Win10/11 上做。
本机直接打包 不可行 Buildozer 在 Windows 原生环境不支持 Android 目标（必须 Linux/Docker/WSL）。本机也没有 Docker 与 WSL。

路线 A：GitHub Actions 出包（一步一步）

依赖说明：buildozer.spec 已默认把 usb4a, usbserial4a 打进 APK， 所以网络模式与 USB-OTG 直连两个都支持。若确定只用网络模式、想减小体积，可把 requirements 里的这两项去掉，并删掉 android.manifest.intent_filters 与 res\xml\device_filter.xml；USB 模式还需 USB_PERMISSION 权限（已加）。

1
在 GitHub 新建一个空仓库（例如 mctc-android），不要勾 README / .gitignore。
2
在本机把 F:\workbuddy\MCTC_Android 整个目录推上去： 
# 在 Git Bash / CMD 里执行（只推这一个目录作为仓库根目录，最省事）
cd /f/workbuddy/MCTC_Android

如果是把整个 F:\workbuddy 当仓库推，就保持 MCTC_Android 不变。
4
打标签触发构建：

路线 B：WSL2 + Buildozer 本地构建（命令清单）

# 1) 管理员 PowerShell 装 WSL2（需要重启，Win10 2004+ / Win11）
wsl --install -d Ubuntu-22.04

# 2) 进入 Ubuntu，装依赖
sudo apt update
sudo apt install -y git zip unzip openjdk-17-jdk autoconf libtool pkg-config \
     zlib1g-dev libncurses5-dev libncursesw5-dev libtinfo5 cmake libffi-dev \
     libssl-dev python3-pip python3-setuptools python3-venv
pip install --user --upgrade Cython virtualenv
pip install --user --upgrade buildozer

# 3) 把源码拷进 WSL（Windows 盘符挂在 /mnt/）
cp -r /mnt/f/workbuddy/MCTC_Android ~/mctc-android && cd ~/mctc-android

# 4) 出包（首次会下载 Android SDK/NDK 并编译 Python+Kivy，约 20-40 分钟）
buildozer -v android debug

# 5) 产物
ls -lh bin/*.apk        # 拷贝回 Windows: cp bin/*.apk /mnt/f/workbuddy/
踩坑提示：WSL2 里编译到一半报内存不足，先限制并行度 export MAKEFLAGS=-j2 再跑；报 No space left on device 就清理 WSL 虚拟盘。 构建中途失败想重来：buildozer android clean 后重跑。

五、现场使用步骤（手机端）

  1. 给串口服务器供电，用网线/或手机连它的 WiFi 热点（NA11x 默认 192.168.3.7，C2000 默认 192.168.4.1）； 手机和串口服务器必须在同一网段。
  2. 先确认串口服务器网页里串口参数是 38400 / 8 / 无校验 / 1，模式是透明传输（或已开 Modbus 网关）。
  3. 打开 APP → 选服务器类型（自动填 IP 与端口）→ 选传输协议 → 点连接。
  4. 连接成功后所有操作按钮才可用（未连接时是灰的）。点一键读取电梯状态， 系统/运行/门/轿内/楼层五张卡一起刷新；打开自动刷新可每 N 秒轮询。
  5. 开关门、1-5 层前门、司机开关、持续开门（200ms 循环）都在"控制指令"页。
  6. AGV 页：进入/退出 AGV 模式、读 AGV 状态、心跳自动发送（默认 30 秒，上限 120 秒）。
  7. "通信日志"页看收发原始帧（蓝色 TX / 绿色 RX），现场排查全靠它。

USB-OTG 直连模式（免串口服务器）额外步骤：

  1. 手机开启 OTG：设置里搜"OTG"（部分机型插上线自动开启）。
  2. OTG 线连手机，USB 转 485 转换器接 OTG 线，A/B 端子接协议转换板（与桌面版同样的接法）。
  3. 打开 APP → "连接方式"选「USB OTG 直连」→ 点扫描 → 在下拉框选识别到的设备（已知 485 转换器会排在前面）。
  4. 首次连接系统弹USB 设备授权框，点"允许"（建议勾选默认）。若误点不允许，需重拔插或到系统设置给本 APP 开 USB 权限。
  5. "站址"填协议板地址（默认 1），点连接。其余操作（读状态/开关门/AGV）与网络模式完全一致。

六、安卓特有的坑（务必看）

现象原因与处理
界面全是方框/豆腐块 字体没注册上。已内置 Noto Sans SC，正常不会；若仍出现，确认 assets\NotoSansSC-Regular.otf 被打包进去（source.include_exts 必须含 otf）。
一联网就闪退 安卓禁止主线程做网络操作。本工程已把所有连接/收发放后台线程，改代码时不要把 socket 操作搬回主线程。
AGV 心跳发着发着断了 安卓会杀后台。现场请保持 APP 在前台、屏幕常亮、关掉电池优化（设置→应用→电池→无限制）。
连不上 / 一直"连接中" 先手机浏览器 ping 不通就说明不在一个网段；再看串口服务器的 TCP 端口是否被别的客户端占了 （多数模块只支持 1-2 路 TCP 连接，电脑上开着 Modbus Poll 时手机就连不上）。
能连上但读不到数据 99% 是协议模式选错：服务器是透传就选「Modbus RTU 透传」，开了网关就选「Modbus TCP 网关」。 其次查串口侧波特率是不是 38400/8N1。
装不上 APK 打开"允许安装未知应用"；若提示"安装包异常"，多半是下载不完整，重新从 Artifacts 下载。
手机是老 32 位机装不上 把 buildozer.spec 的 android.archs 改成 arm64-v8a, armeabi-v7a 重新构建。
USB 扫描列表为空 / 识别不到 ①手机 OTG 未开；②OTG 线或转换器坏了；③芯片不在驱动白名单（仅支持 FTDI/CP210x/CH340/PL2303，杂牌 CH34x 克隆片可能认不出）。 白名单见 res\xml\device_filter.xml。
USB 连上后立刻自动断开 拔线看门狗检测到串口没有真正打开——多半是没点"允许 USB 设备"。重拔插转换器，在系统弹窗点允许（勾默认），再点连接。
